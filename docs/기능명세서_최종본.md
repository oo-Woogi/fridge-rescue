## 1. 문서 개요

### 1.1 목적

본 문서는 "냉장고 구조대(Fridge Rescue)" 서비스의 UI 목업 및 클라이언트와 합의된 정책 결정사항을 기준으로, 화면별 기능·데이터·비즈니스 로직을 정의한 최종 기능명세서이다. 개발팀은 본 문서를 기준으로 구현을 진행하며, 명세 변경이 필요한 경우 관련 이해관계자 합의 후 문서를 갱신한다.

### 1.2 용어 정의

| 용어 | 정의 |
|---|---|
| 구조(하다) | 유통기한이 임박한 식품을 폐기하지 않고 섭취(소비)하는 행위. "먹었어요" 처리와 동일한 의미로 사용 |
| 폐기 | 식품을 소비하지 못하고 버리는 행위. "폐기했어요" 처리 |
| D-day | 유통기한까지 남은 일수. D-0은 당일 만료, D-1은 1일 남음을 의미 |
| 유통기한경과 | D-day가 음수(기한 경과)인 상태를 나타내는 고정 뱃지 문구. 자동 폐기 처리는 되지 않음 |
| 임박 음식 | 유통기한이 3일 이내로 도래하는, 아직 처리되지 않은 식품 |
| 보관 위치 | 식품의 저장 방식 구분: 냉장 / 냉동 / 실온 |

### 1.3 서비스 개요

| 항목 | 내용 |
|---|---|
| 서비스명 | 냉장고 구조대 (Fridge Rescue) |
| 핵심 가치 | 냉장고 속 식품의 유통기한을 관리하여 음식물 쓰레기를 줄이고, 사용자가 식품을 "구조"하도록 돕는 라이프스타일 웹서비스 |
| 핵심 기능 | 회원가입/로그인, 식품 등록·수정·삭제, 유통기한 D-day 계산 및 상태 뱃지, 목록 조회·검색·필터, 상태 처리(구조/폐기), 알림, 통계 대시보드, 설정 |
| 타깃 사용자 | 자취생, 1인 가구, 식재료 관리에 관심 있는 일반 소비자 |
| 플랫폼 | 웹서비스(모바일 우선 반응형), 목업은 모바일 뷰포트 기준 |

### 1.4 전체 기능 구조 (Feature Tree)

클라이언트가 제공한 전체 기능 흐름도(`전체기능.jpg`)를 기준으로 정리한 대분류 구조이다. 세부 항목은 2장 화면별 명세에서 다룬다.

| 대분류 | 주요 하위 구성 |
|---|---|
| 랜딩 페이지 | 서비스 소개, 오늘 구조해야 할 음식(D-Day/위험도 뱃지), 빠른 액션(음식 등록·목록·알림·통계 바로가기), 요약 카드(전체/임박/이번 주 구조·폐기 수) |
| 음식 등록 페이지 | 입력 폼(음식명·카테고리·수량·구매일·유통기한·보관위치·메모), 입력 검증(필수값/날짜 형식), 제출 결과(등록 완료 → 목록/상세 이동) |
| 냉장고 목록 페이지 | 목록 표시(카드형), 검색(음식명), 필터(카테고리/보관위치/상태), 정렬(유통기한 임박순/최근 등록순/이름순) |
| 음식 상세 페이지 | 기본 정보, 상태 정보(보관 중/먹음/폐기/유통기한경과), 버튼 액션(수정/삭제/상태 변경) |
| 음식 수정 페이지 | 기존 정보 불러오기, 수정 폼, 저장(상세·목록 페이지에 즉시 반영) |
| 상태 처리 | 먹었어요(소비 완료 처리, 통계 반영), 폐기했어요(폐기 완료 처리, 통계 반영), 삭제(삭제 확인 → 목록 반영) |
| 알림 페이지 | 알림 목록(오늘 만료/3일 이내 임박/이미 지난 음식), 알림 클릭 시 상세 이동, 알림 기준 설정(D-1/D-3 개별 토글) |
| 통계 대시보드 | 기간별 요약(오늘/이번 주/이번 달), 핵심 지표(구조한 음식 수·폐기한 음식 수·구조율·임박 음식 수), 시각 요소(막대그래프·도넛그래프·비율 표시) |
| 설정 | 사용자 설정(닉네임·비밀번호 수정, 알림 기준), 데이터 관리(샘플 데이터 추가·전체 데이터 삭제), 서비스 정보(프로젝트 소개·문의/FAQ) |
| 공통 UI | 상단 내비게이션, 콘텐츠 카드, 버튼/뱃지 스타일, 하단 탭바, 푸터 브랜드 배너 |

> 원본 다이어그램의 "관리자(선택)" 영역은 후순위 기능으로 분류되어 본 명세서 범위에서 제외한다(5장 참조).

**MVP 범위**

원본 다이어그램은 로그인을 후순위 기능으로 분류하고 있으나, 사용자별 냉장고 데이터를 분리 저장해야 하는 서비스 특성상 로그인/회원가입은 MVP 범위에 포함한다. 다만 간편 로그인, 비밀번호 찾기 등 부가 인증 기능은 범위에서 제외한다.

| 구분 | 포함 기능 |
|---|---|
| MVP 핵심 기능 | 음식 등록 / 목록 조회 / 상세 조회 / 수정·삭제 / 상태 변경 / D-Day 계산 / 알림 / 통계 대시보드 / 검색·필터 / 로그인·회원가입(인증 및 데이터 분리 목적) |
| 후순위 기능(Backlog) | AI 레시피 추천 실연동, 공유 기능, 관리자 페이지 고도화, 간편 로그인, 비밀번호 찾기 |

### 1.6 공통 UI 컴포넌트

#### 1.6.1 하단 탭바 (Bottom Navigation)
- 5개 탭: 홈 / 음식 등록 / 목록 보기 / 통계 / 설정
- 현재 화면의 탭은 그린 계열 강조색으로 활성화 표시
- 음식 상세조회·음식 수정·알림·회원가입·계정 설정·전체데이터삭제·문의 화면은 하단 탭바 없이 상단 back 버튼으로 이전 화면 복귀

#### 1.6.2 상단 헤더 아이콘
- 홈 · 목록 · 통계 화면: 우측 상단에 알림 종 아이콘을 노출하며, 클릭 시 알림(SCR-NOTI) 화면으로 이동
- 로그인 · 설정 화면: 별도의 우측 상단 아이콘 없음

#### 1.6.3 상태 뱃지 (D-day Badge)
식품의 유통기한 임박도에 따라 색상과 문구가 다른 뱃지를 표시한다. D-day가 음수(기한 경과)인 경우 "D+n" 형태 대신 "유통기한경과"라는 고정 문구로 표시한다. 상세 규칙은 [3.3절](#33-상태-산정-로직-d-day--뱃지--확정) 참조.

#### 1.6.4 플로팅 액션 버튼 (FAB)
- 홈, 목록 화면 우측 하단에 오렌지색 원형 "+" 버튼 고정 노출, 클릭 시 음식 등록(SCR-FOOD-ADD)으로 이동

#### 1.6.5 마스코트 캐릭터
- 냉장고 모양 마스코트가 화면 맥락에 맞는 소품(하트, 돋보기, 알림종, 톱니바퀴, 엄지척, 반창고 등)과 함께 등장
- 말풍선 형태의 짧은 응원/안내 카피 동반

#### 1.6.6 확인 모달(Confirm Dialog)
데이터 삭제 등 되돌릴 수 없는 액션은 화면 하단에서 올라오는 바텀시트형 확인 모달을 사용한다. 배경은 반투명 그레이 오버레이로 덮이고, 모달에는 제목·설명·취소/실행 버튼 2개가 노출된다([2.12절](#212-설정--전체-데이터-삭제-scr-settings-delete) 참조).

## 2. 화면별 상세 기능 명세

### 2.1 로그인 (SCR-LOGIN)

**화면 목적**: 사용자 인증을 통해 서비스 이용 권한을 확인하고 홈 화면으로 진입시킨다.

> 간편(소셜) 로그인, 비밀번호 찾기 기능은 제공하지 않는다. 화면 상단에는 별도의 메뉴 아이콘을 두지 않는다.

**구성 요소 및 기능**

| 요소 | 타입 | 설명 / 유효성 규칙 |
|---|---|---|
| 상단 로고 영역 | 표시 | "냉장고 구조대 / FRIDGE RESCUE" 로고 |
| 이메일 입력 | 텍스트 입력(필수) | 이메일 형식 검증. 형식 오류 시 인라인 에러, 로그인 버튼 비활성화 |
| 비밀번호 입력 | 텍스트 입력(필수, 마스킹) | 눈 모양 아이콘 클릭 시 마스킹 표시/해제 토글 |
| 로그인 상태 유지 | 체크박스 | 체크 시 자동 로그인 토큰 장기 보관 |
| 로그인하기 버튼 | 주요 CTA(오렌지) | 입력값 검증 통과 시 활성화. 클릭 시 인증 API 호출 → 성공 시 홈 이동, 실패 시 에러 메시지 |
| 회원가입 링크 | 텍스트 링크 | 회원가입(SCR-SIGNUP) 화면으로 이동 |
| 하단 배너 | 표시 | 서비스 슬로건 및 브랜드 반복 노출 |

**예외 처리**
- 이메일/비밀번호 불일치 시 "이메일 또는 비밀번호가 올바르지 않습니다" 노출
- 네트워크 오류 시 재시도 안내 토스트 노출

### 2.2 회원가입 (SCR-SIGNUP)

**화면 목적**: 신규 사용자가 닉네임·이메일·비밀번호를 입력해 계정을 생성한다.

> 회원가입은 별도의 약관 동의 절차 없이 닉네임·이메일·비밀번호·비밀번호 확인 4개 필드의 유효성 검증만으로 완료된다.

**구성 요소 및 기능**

| 요소 | 타입 | 설명 / 유효성 규칙 |
|---|---|---|
| 상단 헤더 | 내비게이션 | back 버튼 + "회원가입" 타이틀 |
| 안내 영역 | 표시 | 말풍선("냉장고 구조대와 함께해요!") + 마스코트, "몇 가지 정보만 입력하면…" 서브카피 |
| 닉네임 | 텍스트 입력(필수) | 플레이스홀더 "예: 구조대장냉장고". 1자 이상, 중복 확인 필요(서버 검증) |
| 이메일 | 텍스트 입력(필수) | 이메일 형식 검증, 중복 가입 여부 서버 확인 |
| 비밀번호 | 텍스트 입력(필수, 마스킹) | "영문, 숫자 포함 8자 이상 입력하세요" 힌트 상시 노출. 눈 아이콘으로 마스킹 토글 |
| 비밀번호 확인 | 텍스트 입력(필수, 마스킹) | 비밀번호와 일치 여부 실시간 검증. 불일치 시 에러 문구, 일치 시 입력창 테두리 그린 처리 |
| 가입하고 시작하기 | 주요 CTA(오렌지) | 4개 필드 검증을 모두 통과해야 활성화. 클릭 시 가입 API 호출 → 성공 시 홈 이동 |
| 로그인 링크 | 텍스트 링크 | "이미 계정이 있으신가요? 로그인" → 로그인(SCR-LOGIN) 이동 |

> 이용약관/개인정보처리방침에 대한 별도 동의 절차 없이 가입이 가능하다. 법적 고지 문구(예: "가입 시 이용약관에 동의한 것으로 간주됩니다")를 하단에 안내 문구로 대체할지 여부는 서비스 정책팀 확인이 필요하다.

### 2.3 홈 (SCR-HOME)

**화면 목적**: 로그인 직후 진입하는 메인 대시보드. 오늘 처리가 필요한 식품과 이번 주 요약 지표를 보여주고 핵심 기능으로 연결한다.

**구성 요소 및 기능**

| 요소 | 타입 | 설명 / 데이터 소스 |
|---|---|---|
| 상단 헤더 | 표시 | 로고 + 알림 종 아이콘(우측 상단). 클릭 시 알림(SCR-NOTI) 이동 |
| 인사 메시지 | 동적 텍스트 | "오늘도 냉장고를 구조해볼까요? (M/D 요일)" 형태로 당일 날짜 자동 표기 |
| 오늘 구조해야 할 음식 | 가로 스크롤 카드 | 보관 중 상태이며 D-day가 1 이하(D-1, D-0)인 식품을 임박순으로 카드 노출. 유통기한이 이미 지난(유통기한경과) 항목은 이 영역에 노출하지 않고 목록·알림의 "이미 지난 음식"에서만 확인 |
| 임박 음식으로 레시피 추천받기 | 배너 버튼 | 클릭 시 "준비 중인 기능이에요" 안내 토스트만 노출(실 연동 보류, 4.3절 참조) |
| 이번 주 요약 | 통계 카드 4종 | 전체 음식/임박 음식/이번 주 구조/이번 주 폐기 개수, 서버 집계 API로 실시간 조회 |
| FAB(+) | 버튼 | 음식 등록(SCR-FOOD-ADD) 이동 |
| 하단 탭바 | 내비게이션 | 5개 탭, "홈" 활성화 |

> "오늘 구조해야 할 음식" 카드가 없을 경우 빈 상태(empty state) 문구 노출. 화면 진입/포그라운드 복귀 시 데이터 재조회.

### 2.4 음식 등록 (SCR-FOOD-ADD)

**화면 목적**: 신규 식품 정보를 입력해 냉장고 목록에 추가한다.

> 별도의 확인(2단계)·완료(3단계) 화면 없이, 단일 화면에서 입력 후 즉시 등록이 처리된다.

**입력 필드**

| 필드명 | 필수 | 입력 형태 | 기본값 / 옵션 | 유효성 규칙 |
|---|---|---|---|---|
| 음식명 | 필수(*) | 텍스트 입력 | 플레이스홀더 "예: 상추, 토마토, 두부 등" | 1자 이상, 공백만 입력 불가 |
| 카테고리 | 필수(*) | 단일 선택 pill | 유제품/채소/과일/육류/기타 | 5개 중 1개 필수 선택 |
| 수량 | 선택 | 스테퍼(−/+) | 기본값 1, 최소 1 | |
| 구매일 | 선택 | 날짜 선택 | 기본값 오늘 날짜 자동 세팅 | |
| 유통기한 | 필수(*) | 날짜 선택 | 플레이스홀더 "연도-월-일" | 구매일 이후 권장, 미입력 시 등록 불가 |
| 보관 위치 | 선택 | 단일 선택 pill | 냉장/냉동/실온 (기본값 "냉장") | 1개 선택 |
| 메모 | 선택 | 멀티라인 텍스트 | 플레이스홀더 "예: 샐러드용으로 구매했어요" | 길이 제한(예: 100자) 권장 |

**등록 전 체크 항목**
- 정확한 유통기한을 확인했어요
- 보관 위치를 미리 정했어요
- 수량과 상태를 올바르게 입력했어요

> 세 항목 체크 여부가 "등록하기" 활성화 조건에 포함되는지는 별도 정책으로 남아 있다(권장: 필수 체크 시에만 등록 가능).

**액션 버튼**

| 버튼 | 설명 |
|---|---|
| 취소 | 입력 내용을 폐기하고 이전 화면(홈 또는 목록)으로 복귀 |
| 등록하기 → | 필수 항목 검증 통과 시 활성화. 클릭 시 등록 API 호출 → 성공 시 음식 상세조회 화면으로 즉시 이동, 실패 시 에러 메시지 |

---

### 2.5 음식 상세조회 (SCR-FOOD-DETAIL)

**화면 목적**: 개별 식품의 상세 정보를 확인하고, 레시피 추천 연동(보류) 및 상태 변경(먹었어요/폐기했어요/수정) 액션을 수행한다.

**구성 요소 및 기능**

| 요소 | 타입 | 설명 |
|---|---|---|
| 상단 헤더 | 표시/내비게이션 | back 버튼 + 음식명, 우측 상단 마스코트 아이콘 |
| 식품 요약 카드 | 표시 | 카테고리 대표 이모지, 음식명, 상태뱃지(D-day·위험해요 / 유통기한경과 등), "유통기한까지 N일 남았어요" 문구, 처리상태 칩("보관 중" 등) |
| 상세 정보 리스트 | 표시 | 카테고리, 수량, 구매일, 유통기한, 보관위치, 메모(값 없으면 "—") |
| 이 재료로 레시피 추천받기 | 버튼(보류) | UI 버튼은 유지. 클릭 시 "준비 중인 기능이에요" 토스트만 노출, 실제 추천 로직은 미연동(4.3절) |
| 보관 꿀팁 | 표시(정보성, 구현 확정) | 카테고리와 무관하게, 10개 팁 목록 중 화면 진입 시마다 1개를 무작위로 노출. 목록은 3.5절 참조 |
| 수정 버튼 | 보조 버튼 | 음식 수정(SCR-FOOD-EDIT)으로 현재 데이터 전달 |
| 먹었어요 버튼 | 주요 액션(그린) | 상태를 "구조(섭취완료)"로 변경, 통계에 "구조" 카운트 반영 후 이전 화면 복귀 |
| 폐기했어요 버튼 | 주요 액션(레드) | 상태를 "폐기"로 변경, 통계에 "폐기" 카운트 반영 후 이전 화면 복귀(확인 다이얼로그 권장) |

### 2.6 음식 수정 (SCR-FOOD-EDIT)

**화면 목적**: 이미 등록된 식품 정보를 수정한다. 필드 구성은 등록 화면과 동일하되 기존 값이 프리필된다.

**입력 필드 (등록 화면과의 차이점)**

| 필드명 | 차이점 |
|---|---|
| 음식명 / 카테고리 / 보관 위치 / 구매일 / 메모 | 기존 값 프리필 |
| 수량 | 기존 값 프리필 + 하단에 "이전: N개" 참고 텍스트 |
| 유통기한 | 기존 값 프리필 + 하단에 "이전: YYYY-MM-DD" 참고 텍스트 |

> 등록 화면의 "등록 전 체크 항목"은 수정 화면에는 노출되지 않는다.

**액션 버튼**

| 버튼 | 설명 |
|---|---|
| 취소 | 변경사항을 저장하지 않고 이전 화면으로 복귀 |
| 저장하기 → | 검증 통과 시 활성화. 클릭 시 수정 API 호출 → 성공 시 상세 화면 복귀, 변경 정보 즉시 반영 |

### 2.7 목록 / 냉장고 목록 (SCR-FOOD-LIST)

**화면 목적**: 등록된 모든 식품을 검색·필터·정렬하여 조회하고, 개별 항목에서 바로 상태를 변경한다.

**구성 요소 및 기능**

| 요소 | 타입 | 설명 |
|---|---|---|
| 상단 헤더 | 표시 | "냉장고 목록" 타이틀 + 알림 종 아이콘(SCR-NOTI 이동) |
| 검색창 | 텍스트 입력 | 음식명 부분일치 실시간 필터링 |
| 카테고리 필터 | 탭/pill | 전체(기본)/유제품/채소/과일/육류/기타, 검색어와 AND 조건 |
| 결과 카운트 | 표시 | "총 N개의 음식이 있어요" |
| 정렬 옵션 | 드롭다운 | 기본값 "유통기한 임박순"(유통기한경과 항목은 최상단 또는 최하단 고정 노출 정책 확정 필요) |
| 식품 리스트 아이템 | 카드 리스트 | 아이콘, 음식명, 보관위치·카테고리·수량, 상태뱃지(D-day 또는 유통기한경과). 클릭 시 상세 이동 |
| 수정하기 / 먹었어요 / 폐기 버튼 | 인라인 액션 | 각각 수정 이동, 구조 처리, 폐기 처리(확인 다이얼로그 권장) |
| FAB(+) | 버튼 | 음식 등록 이동 |
| 하단 탭바 | 내비게이션 | "목록 보기" 활성화 |

### 2.8 통계 (SCR-STATS)

**화면 목적**: 사용자의 식품 관리 활동(구조/폐기)을 기간별로 집계·시각화한다.

> 카테고리별 구조 현황, 상태 비중, 최근 요약은 별도의 상세/더보기 화면 없이 본 화면에서 요약 정보만 제공한다. 최근 요약은 최대 5건까지만 노출한다.

**구성 요소 및 기능**

| 요소 | 타입 | 설명 |
|---|---|---|
| 상단 헤더 | 표시 | 로고 + 알림 종 아이콘(우측 상단). 클릭 시 알림(SCR-NOTI) 이동 |
| 기간 탭 | 단일 선택 | 오늘 / 이번 주 / 이번 달 |
| 핵심 지표 카드 4종 | 통계 카드 | 구조한 음식 수, 폐기한 음식 수, 구조율(%), 임박 음식 수. 전기간 대비 증감(▲/▼) 표기 |
| 카테고리별 구조 현황 | 막대그래프 | 채소/유제품/과일/육류/기타별 구조 처리 개수를 전체 노출(추가 이동 없음) |
| 상태 비중 | 도넛그래프 | 정상/임박/폐기 비중(%), 중앙에 총 개수. 추가 이동 없음 |
| 최근 요약 | 리스트(최대 5건) | 최근 처리 이력(이모지·음식명·처리결과 뱃지·상대시각), 5건 초과분은 노출하지 않음 |
| 하단 탭바 | 내비게이션 | "통계" 활성화 |

**지표 산정 로직**

| 지표 | 산정식 / 기준 |
|---|---|
| 구조한 음식 수 | 선택 기간 내 상태가 "구조"로 변경된 식품 건수 |
| 폐기한 음식 수 | 선택 기간 내 상태가 "폐기"로 변경된 식품 건수 |
| 구조율 | 구조 수 ÷ (구조 수 + 폐기 수) × 100, 분모 0이면 0% 처리 |
| 임박 음식 수 | 조회 시점 기준, 보관 중 식품 중 임박 기준(3.3절)에 해당하는 건수 |
| 증감(▲/▼) | 직전 동일 기간 대비 증감량 |

### 2.9 알림 (SCR-NOTI)

**화면 목적**: 유통기한이 임박했거나 지난 식품을 모아 보여주고, 알림 수신 여부를 설정한다.

> "이미 지난 음식" 필터는 유통기한경과 뱃지가 부여된 식품을 대상으로 한다.

**구성 요소 및 기능**

| 요소 | 타입 | 설명 |
|---|---|---|
| 상단 헤더 | 내비게이션 | back 버튼 + "알림" 타이틀 |
| 검색창 | 텍스트 입력 | 음식명 기준 실시간 필터링 |
| 필터 탭 | pill | 전체(기본)/오늘 만료/3일 이내 임박/이미 지난 음식 |
| 오늘 만료 섹션 | 그룹 리스트 | D-0 식품. 아이콘, 음식명, "유통기한이 D-0 남았어요", D-day 뱃지 |
| 3일 이내 임박 섹션 | 그룹 리스트 | D-1~D-3 식품 |
| 이미 지난 음식 섹션 | 그룹 리스트 | 유통기한경과 뱃지가 부여된 식품. 목업 스크린샷상 현재 0건으로 비노출 |
| 알림 기준 설정 | 토글 스위치 2종 | "D-1 알림"(기본 ON) / "D-3 알림"(기본 ON). 매일 KST 08:00에 해당 조건을 만족하는 식품에 대해 Push 발송 |
| 하단 탭바 | 내비게이션 | 노출(활성 탭 없음) |

**알림(Push) 발송 로직 (확정)**

| 항목 | 내용 |
|---|---|
| 발송 시각 | 매일 한국시간(KST) 오전 8시 고정 (사용자별 시각 커스텀 미지원) |
| D-1 알림 | ON일 경우, 유통기한 1일 전(D-1)에 해당하는 식품에 대해 오전 8시 Push 발송 |
| D-3 알림 | ON일 경우, 유통기한 3일 전(D-3)에 해당하는 식품에 대해 오전 8시 Push 발송 |
| 토글과 화면 리스트의 관계 | 두 토글은 Push 발송 여부만 제어하며, 알림 화면 내 "오늘 만료"/"3일 이내 임박" 리스트업은 토글 상태와 무관하게 항상 D-day 기준으로 노출 |
| 항목 클릭 | 음식 상세조회(SCR-FOOD-DETAIL)로 이동 |

### 2.10 설정 (SCR-SETTINGS)

**화면 목적**: 사용자 계정, 알림, 데이터 관리 및 서비스 정보를 확인/변경한다.

> "닉네임 수정" 메뉴에는 우측에 현재 닉네임 값이 함께 노출된다(예: "구조대장냉장고 >"). 클릭 시 계정 설정(SCR-SETTINGS-PROFILE) 화면으로 이동한다.

**메뉴 구성**

| 그룹 | 항목 | 타입 | 설명 |
|---|---|---|---|
| 사용자 설정 | 닉네임 수정 | 이동형 메뉴(>), 현재값 노출 | 계정 설정(SCR-SETTINGS-PROFILE) 이동 |
| 사용자 설정 | 알림 설정 | 이동형 메뉴(>) | 알림(SCR-NOTI) 화면의 "알림 기준 설정" 영역으로 이동 |

### 3.3 상태 산정 로직 (D-day & 뱃지) — 확정

D-day = 유통기한(expiry_date) − 오늘 날짜(today), 일 단위 계산.

| 조건 | 뱃지 표기 | 색상(권장) | 비고 |
|---|---|---|---|
| D-day ≤ 1 (D-1, D-0) | D-0 / D-1 · 위험해요 | 레드/오렌지 계열 | 홈 "오늘 구조해야 할 음식"에 노출 |
| 2 ≤ D-day ≤ 3 | D-2 / D-3 | 옐로 계열 | 알림 화면 "3일 이내 임박" 그룹 |
| D-day ≥ 4 | D-N | 그린 계열 | 정상 보관 상태 |
| D-day < 0 (기한 경과) | 유통기한경과 (고정 문구) | 레드 계열 | 자동 폐기 전환 없음. 상태값은 "보관 중" 유지, 뱃지만 별도 표기. 알림 화면 "이미 지난 음식" 그룹 |

> 기한 경과 시 자동으로 폐기 처리되지 않으며, "유통기한경과" 뱃지만 부여된다. FAQ 4번 답변의 "'만료' 상태" 표현은 화면 뱃지 문구(유통기한경과)와 통일이 필요하다(부록 B 참조).

## 4. 주요 정책 및 설계 결정 사항

개발 과정에서 참고할 수 있도록, 목업만으로는 알 수 없는 정책적 판단이 필요했던 사항과 그 결정 결과를 정리한다.

### 4.1 확정된 정책

| 영역 | 확정된 내용 |
|---|---|
| 인증 | 간편(소셜) 로그인, 비밀번호 찾기는 제공하지 않는다. 회원가입은 약관 동의 없이 4개 필드(닉네임/이메일/비밀번호/비밀번호 확인) 검증만으로 완료된다. |
| 음식 등록 | 단계(Stepper) 구분 없이 단일 화면에서 입력과 동시에 등록이 완료된다. |
| AI 레시피 추천 | UI(버튼)는 제공하되, 클릭 시 "준비 중인 기능이에요" 안내만 노출하고 실제 추천 로직은 연동하지 않는다(4.3절). |
| 보관 꿀팁 | 카테고리 구분 없이 10개 문구 풀 중 화면 진입 시마다 1개를 무작위로 노출한다(3.5절). |
| 통계 화면 | 카테고리별 구조 현황·상태 비중·최근 요약에는 별도의 상세/더보기 이동을 두지 않고, 화면 내 정보만 제공한다. |
| 알림 발송 시각 | 한국시간(KST) 매일 오전 8시로 고정하며, 사용자별 커스텀 시각은 지원하지 않는다. |
| 유통기한 경과 처리 | 자동으로 폐기 처리되지 않으며, "유통기한경과" 뱃지만 부여한다(3.3절). |
| 데이터 삭제 | 등록된 음식 데이터 전체를 삭제 대상으로 하며, 삭제 전 확인 모달을 반드시 거친다(4.4절). |
| 화면 상단 아이콘 | 홈·목록·통계 화면은 알림 종 아이콘을, 로그인·설정 화면은 별도 아이콘을 두지 않는다. |

### 4.2 열린 이슈 (Open Issues)

아직 결정되지 않아, 개발 착수 전 관련 담당자 확인이 필요한 항목이다.

| 영역 | 확인 필요 사항 |
|---|---|
| 등록 전 체크 항목의 필수 여부 | 3개 체크박스가 "등록하기" 버튼 활성화 조건에 포함되는지 여부 |
| 목록 정렬 시 유통기한경과 항목 위치 | "유통기한 임박순" 정렬에서 이미 지난 음식을 최상단에 둘지, 최하단에 둘지 |
| 계정 설정 · 비밀번호 변경 시 본인 확인 | "현재 비밀번호" 입력값에 대한 서버 측 일치 검증 로직 반영 필요 |
| 계정 설정 · 비밀번호 필드 전체 미입력 시 동작 | 닉네임만 변경하고 비밀번호 3필드를 모두 비워둔 경우 정상 저장되는지 |
| 보관 꿀팁 중복 노출 방지 여부 | 직전에 노출된 문구가 연속으로 다시 노출되는 것을 막을지 여부(3.5절) |
| 회원가입 시 법적 고지 문구 | 약관 동의 체크박스가 없는 만큼, 가입 시 이용약관/개인정보처리방침에 대한 최소한의 고지 문구를 하단에 안내할지 여부 |

### 4.3 AI 레시피 추천 처리 방식

- 홈 배너, 음식 상세조회 버튼 등 UI 요소는 제공한다
- 클릭 시 실제 추천 결과 대신 "준비 중인 기능이에요" 형태의 안내 토스트만 노출한다
- 추천 알고리즘/외부 API 연동은 후순위 기능으로 별도 진행한다(5장 참조)

### 4.4 데이터 삭제 정책 상세

- 삭제 대상: 사용자가 등록한 음식(Food) 데이터 전체
- 삭제 제외(가정): 사용자 계정 정보(이메일/닉네임/비밀번호), 통계 이력 원본 로그 — 명시적 언급이 없어 유지하는 것으로 가정
- 삭제 확인: 바텀시트 모달에서 "취소/삭제하기" 2단계 확인 절차를 거침(2.12절)
- 삭제 후 복구는 불가하며, FAQ 11번 문항에 "복구 불가" 안내 문구 추가 필요

### 4.5 FAQ 문구 정합화

- FAQ 1번 답변의 "설정한 알림일(기본 만료 3일 전)" 문구를 "매일 오전 8시(KST)" 발송 시각에 맞게 갱신 필요
- FAQ 4번 답변의 "'만료' 상태" 표현을 화면 뱃지 문구인 "유통기한경과"로 통일 필요
- FAQ 6번(로그인 없이 사용 가능 여부) 답변에 회원가입이 약관 동의 없이 4개 필드만으로 간소화되었음을 함께 안내하면 사용자 혼란을 줄일 수 있음

## 6. 화면 흐름 (User Flow)

- 로그인 → (인증 성공) → 홈
- 로그인 → (회원가입 링크) → 회원가입 → (가입 완료) → 홈
- 홈 → (FAB +) → 음식 등록 → (등록하기) → 음식 상세조회
- 홈 → (오늘 구조해야 할 음식 카드) → 음식 상세조회
- 홈 → (알림 종 아이콘) → 알림
- 음식 상세조회 → (수정) → 음식 수정 → (저장하기) → 음식 상세조회
- 음식 상세조회 → (먹었어요 / 폐기했어요) → 이전 화면(홈 또는 목록)
- 목록 → (항목 클릭) → 음식 상세조회
- 목록 → (수정하기 / 먹었어요 / 폐기, 인라인) → 목록 내 즉시 반영
- 목록 → (FAB +) → 음식 등록
- 알림 → (항목 클릭) → 음식 상세조회
- 설정 → (닉네임 수정) → 계정 설정 → (변경사항 저장하기) → 설정
- 설정 → (전체 데이터 삭제) → 삭제 확인 모달 → (삭제하기) → 설정(음식 데이터 전체 제거 완료)
- 설정 → (문의) → 문의/FAQ
- 설정 → (로그아웃) → 로그인

## 8. 부록 B — 개정 이력

본 명세서는 2026-09-07~09-08 사이 총 3차례의 목업 검토와 정책 논의를 거쳐 확정되었다. 참고용으로 각 단계의 주요 결정 사항을 기록한다.

### 8.1 v1.0 → v2.0

회원가입/회원정보수정/문의(FAQ) 화면을 신규 추가하고, 비밀번호 찾기·간편로그인·음식 등록 2·3단계를 삭제했으며, 아래 12건의 정책을 확정하였다.

| No | 항목 | 결정 내용 |
|---|---|---|
| 1 | 회원가입 | 입력폼 화면 신규 추가 |
| 2 | 비밀번호 찾기 | 기능 및 진입 링크 삭제 |
| 3 | 간편 로그인 | 소셜 로그인 버튼 및 관련 문구 삭제 |
| 4 | 음식 등록 2·3단계 | 단계(Stepper) 제거, 단일 화면에서 즉시 등록 처리 |
| 5 | AI 레시피 추천 | UI 버튼은 유지하되 실제 추천 로직 연동은 보류 |
| 6 | 보관 꿀팁 데이터 | 카테고리별 보관 팁 콘텐츠 매핑(이후 v3.0에서 랜덤 노출 방식으로 재변경) |
| 7 | 통계 화면 상세 이동 | "전체보기"(2곳)·"더보기" 링크 삭제, 목록 내 정보만 표시 |
| 8 | 알림 발송 시각 | 한국시간(KST) 매일 오전 8시로 고정 |
| 9 | 유통기한 경과 처리 | 자동 폐기 전환 없이 "유통기한경과" 뱃지로 표시 |
| 10 | 데이터 삭제 정책 | 등록된 음식 데이터 전체 삭제 + 삭제 전 확인 팝업 노출 |

# CLAUDE.md

이 파일은 Claude Code가 본 프로젝트에서 작업할 때 반드시 따라야 하는 지침을 정의합니다.

## 프로젝트 개요

- 본 프로젝트는 **웹앱(Web Application)** 입니다. 모바일 네이티브 앱이 아니며, 브라우저에서 동작하는 웹 서비스로 구현합니다.
- **대응 기기: 아이폰 14 Pro, 아이폰 15** 화면 기준으로 반응형/레이아웃을 구현합니다. 데스크톱 대응이 아닌 해당 기기들의 뷰포트(화면 크기, 세이프에어리어 등)를 기준으로 UI를 맞춥니다.
  - 아이폰 14 Pro: 393 x 852 (CSS px 기준, @3x, 다이나믹 아일랜드)
  - 아이폰 15: 393 x 852 (CSS px 기준, @3x, 다이나믹 아일랜드)
  - 두 기종의 뷰포트 크기가 동일하므로 하나의 모바일 웹 레이아웃으로 대응 가능하나, 노치/다이나믹 아일랜드 등 세이프에어리어(safe-area-inset) 처리를 고려하여 구현합니다.
  - 와이어프레임(`images/`)도 이 기준 뷰포트에 맞춰 그려진 것으로 간주하고, 임의로 데스크톱용 레이아웃이나 다른 해상도 기준으로 변형하지 않습니다.

## 기술 스택

- **Frontend**: React
- **Backend**: Django
- **Database**: MySQL

임의로 다른 프레임워크/라이브러리/DB로 대체하거나 추가 스택(예: Next.js, FastAPI, PostgreSQL 등)을 도입하지 않습니다. 위 스택 범위 내에서만 구현하며, 스택 변경이 필요하다고 판단되는 경우에도 임의로 진행하지 말고 반드시 사용자에게 먼저 확인합니다.

- Frontend(React)와 Backend(Django)는 `API 명세서.md`에 정의된 REST API를 통해 통신합니다.
- Backend(Django)는 `DB설계서.md`에 정의된 스키마를 기준으로 MySQL과 연동합니다.
- 프로젝트 구조(폴더 분리, 네이밍 등)는 React/Django/MySQL 조합에서 통상적으로 쓰이는 관례를 따르되, 관례에서 크게 벗어나야 하는 경우 사용자에게 먼저 확인합니다.

## 프로젝트 참조 문서

작업 시작 전 아래 문서를 반드시 확인하고, 구현 내용이 문서와 어긋나지 않는지 항상 검증합니다.

- `기능명세서_최종본.md` — 기능 요구사항의 단일 진실 공급원(source of truth). 화면/기능 구현 범위와 동작은 이 문서를 기준으로 판단합니다.
- `API 명세서.md` — 프론트엔드/백엔드 연동 시 엔드포인트, 요청/응답 스펙의 기준 문서입니다. 임의로 API 스펙을 추측하거나 변경하지 않습니다.
- `DB설계서.md` — 데이터 모델, 테이블/컬럼 구조, 관계의 기준 문서입니다. 스키마 관련 작업 시 반드시 참조합니다.
- `시스템.png` — 시스템 아키텍처 다이어그램. 모듈 간 관계, 데이터 흐름을 파악할 때 참조합니다.
- `images/` 폴더 — 와이어프레임 및 화면 참조 이미지가 위치합니다. 화면을 구현할 때 이 폴더 안의 이미지를 실제로 열어보고 그 내용을 근거로 구현합니다.

문서나 이미지가 없거나 내용이 모호한 경우, 임의로 내용을 추측해서 채우지 말고 사용자에게 확인을 요청합니다.

## 와이어프레임 처리 원칙 (매우 중요)

- **원본 유지 원칙**: `images/` 폴더의 와이어프레임 이미지는 임의로 수정하거나 재해석하지 않습니다. 레이아웃, 요소 배치, 화면 구성 요소, 흐름은 와이어프레임에 그려진 그대로를 기준으로 구현합니다.
- 와이어프레임에 없는 요소를 임의로 추가하거나, 있는 요소를 임의로 제거/재배치하지 않습니다.
- 와이어프레임의 표현이 불명확하거나 텍스트 명세와 충돌하는 경우, 임의로 판단하여 진행하지 말고 어떤 해석이 맞는지 사용자에게 확인합니다.
- 와이어프레임을 기반으로 화면을 구현할 때마다, 해당 화면에 대응하는 이미지 파일명을 코드 주석 또는 커밋 메시지 등에 명시하여 추적 가능하게 합니다.

## 구현 시 편집 가능성 요구사항 (매우 중요)

구현된 화면은 사용자가 세부 사항(텍스트, 색상, 레이아웃 값, 컴포넌트 속성 등)을 직접 수정할 수 있는 구조로 구현합니다.

- 하드코딩된 매직 넘버/텍스트를 최소화하고, 화면별 설정값(카피, 색상, 크기, 간격 등)은 컴포넌트 상단 또는 별도 설정 파일(props, config, 상수 객체 등)로 분리하여 한눈에 찾아 수정할 수 있도록 합니다.
- 컴포넌트는 재사용 가능하고 단일 책임을 갖도록 분리하여, 특정 화면의 특정 요소만 콕 집어 수정할 수 있게 구조화합니다.
- 스타일은 인라인으로 흩어놓지 않고 일관된 방식(예: CSS 변수, Tailwind 유틸리티, styled 객체 등 프로젝트에서 채택한 방식)으로 관리하여 세부 조정이 쉽도록 합니다.
- 향후 수정 요청 시 "어느 파일의 어느 부분을 고치면 되는지"가 명확하도록 파일/폴더 구조와 네이밍을 명확히 합니다.

## 작업 절차

1. `기능명세서_최종본.md`, `API 명세서.md`, `DB설계서.md`, `시스템.png`를 확인하여 해당 작업 범위를 파악합니다.
2. 구현할 화면에 대응하는 `images/` 폴더 내 와이어프레임 이미지를 실제로 열어 확인합니다.
3. 와이어프레임의 레이아웃/구성을 원본 그대로 따르되, 세부값은 이후 수정이 쉬운 구조로 구현합니다.
4. API 연동이 필요한 경우 `API 명세서.md`의 스펙을 그대로 따릅니다.
5. 데이터 저장/조회가 필요한 경우 `DB설계서.md`의 스키마를 그대로 따릅니다.
6. 구현 후, 와이어프레임 원본과 실제 구현 화면을 비교하여 임의 수정이 발생하지 않았는지 점검합니다.

## 하지 말아야 할 것

- 와이어프레임 이미지 파일 자체를 편집/덮어쓰기 하지 않습니다 (읽기 전용 참조 자료로만 사용).
- 명세서에 없는 기능을 임의로 추가하지 않습니다.
- API/DB 스펙을 명세서와 다르게 임의로 변경하지 않습니다.
- 근거 문서나 이미지를 확인하지 않고 추측만으로 화면을 구현하지 않습니다.
